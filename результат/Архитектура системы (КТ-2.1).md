# Архитектура системы (Technical Design Document)

## 1. Определение документа
Документ описывает архитектуру Faunistica_4.0 — систему для извлечения и структурирования данных о находках пауков из научных публикаций, с веб‑интерфейсом и Telegram‑ботом для работы волонтёров.

## 2. Назначение документа
- Зафиксировать целостную архитектуру проекта и роли компонентов.
- Объяснить выбор технологий и их соответствие задачам обработки данных.
- Дать единый контекст для разработки, сопровождения и дальнейшего развития.

## 3. Структура документа (заполненная версия)

### 3.1. Общая схема архитектуры (System Context / Container Diagram)
**Контекст:**
- Пользователь‑волонтёр работает через веб‑интерфейс и Telegram‑бот.
- Администратор получает обращения в Telegram‑чат поддержки.
- Система хранит данные в PostgreSQL, выполняет валидацию, геокодирование и экспорт.

**Текстовая схема (контейнеры):**
```
[Пользователь] ──HTTP──> [Frontend (React/Vite)] ──HTTP API──> [Backend (FastAPI)] ──SQL──> [PostgreSQL]
                                     │                                   │
                                     │                                   ├─> [Геокодер Nominatim (geopy)]
                                     │                                   ├─> [Справочники: CSV/JSON]
                                     │                                   └─> [Экспорт XLSX/CSV]
[Пользователь] ──Telegram──> [Telegram Bot (aiogram)] ──DB/API──> [Backend + PostgreSQL]
[Администратор] <─Telegram─ [Support Chat] <─ уведомления ─ [Backend]
```

### 3.2. Стек технологий с обоснованием
**Backend**
- **FastAPI** — быстрый async‑фреймворк для REST API с автоматической схемой и валидацией.
- **SQLAlchemy + asyncpg** — асинхронная работа с PostgreSQL, богатая модель данных.
- **Pydantic** — строгая схема и валидация данных записей.
- **Alembic** — миграции БД.
- **aiogram** — Telegram‑бот с FSM для регистрации, поддержки и статистики.
- **SlowAPI** — rate limiting для защиты от злоупотреблений.
- **Pandas + openpyxl** — импорт/экспорт таблиц (CSV/XLSX).

**Frontend**
- **React 19 + Vite** — современный SPA для удобной работы волонтёров.
- **react‑router** — маршруты (главная, форма, статистика, профиль и т.д.).
- **i18next** — локализация интерфейса.
- **axios** — доступ к API.

**Инфраструктура**
- **PostgreSQL 15** — основная реляционная БД.
- **Docker Compose** — локальный запуск БД и pgAdmin.

### 3.3. Диаграмма базы данных (ER — текстовое описание)
Ключевые сущности и связи:
- **users** — пользователи/волонтёры (Telegram ID, имя, язык, токены, контакты).
- **publs** — научные публикации и их метаданные.
- **event_records** — основная таблица событий/находок (место, дата, таксономия, численность и пр.).
- **records** — промежуточные записи и черновики (autosave), связанные с пользователем и публикацией.
- **actions** — журнал действий пользователя (логирование событий).
- **spiders** — таблица экспорта в формат DarwinCore (для выгрузок/отчётности).

Связи:
- `users (1) ── (N) event_records`
- `publs (1) ── (N) event_records`
- `users (1) ── (N) actions`

### 3.4. Ключевые программные модули
**Backend API**
- **Auth**: логин, logout, refresh токенов.
- **Users**: профиль, фото, поиск по пользователям, статистика.
- **Publications**: выдача текущих публикаций, отметка завершения, комментарии.
- **Records**: создание, обновление, отправка, удаление, импорт/экспорт.
- **Taxonomy**: подсказки и автозаполнение таксонов.
- **Geo**: подсказки регионов и обратное геокодирование координат.
- **Statistics**: агрегированные показатели проекта и пользователя.
- **Support**: отправка обращения в поддержку.

**Telegram Bot**
- Регистрация пользователя (шаги FSM, валидация данных).
- Команды статистики и поддержки.
- Админ‑функции (ответы и логи) через отдельный чат.

**Frontend**
- Главная страница, инструкция, форма заполнения, профиль, статистика, обратная связь.

### 3.5. Ключевые алгоритмы / бизнес‑процессы
**Процесс регистрации (бот + сайт)**
1. Пользователь запускает бота `/start`, проходит `/register`.
2. Бот собирает данные (имя, возраст, предпочтения, язык).
3. Пользователь использует логин/пароль для входа на сайт.

**Заполнение записи**
1. Пользователь получает публикацию и открывает форму.
2. Заполняет административные/гео/таксон/материальные поля.
3. Система валидирует запись и сохраняет (autosave/submit).
4. Возможен экспорт результатов в XLSX/CSV.

**Геокодирование и таксономия**
- Конвертация координат DMS → десятичные градусы.
- Получение названий локаций через Nominatim.
- Подсказки таксонов на основе локального справочника.

**Поддержка**
- Пользователь отправляет запрос через сайт или бота.
- Сообщение доставляется в админ‑чат Telegram.

## 4. Заключение
Архитектура Faunistica_4.0 построена вокруг связки Web‑интерфейса, FastAPI и Telegram‑бота с единой PostgreSQL‑БД. Такое разделение упрощает масштабирование, обеспечивает гибкий интерфейс для волонтёров и централизованный контроль данных.
